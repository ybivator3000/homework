# Модуль 5

## Описание

Kafka
Реализовать микросервис(notification-service) для отправки сообщения на почту при удалении или добавлении пользователя.
Использовать необходимые модули spring и kafka.
При удалении или создании юзера приложение, реализованное до этого(user-service), должно отправлять сообщение в kafka, в котором содержится информация об операции(удаление или создание) и email юзера.
Новый микросервис(notification-service) должен получить сообщение из kafka и отправить сообщение на почту юзера в зависимости от операции: удаление - Здравствуйте! Ваш аккаунт был удалён. Создание - Здравствуйте! Ваш аккаунт на сайте ваш сайт был успешно создан.
Также отдельно добавить API, которая будет отправлять сообщение на почту(почти тот же функционал, что и через кафку).
Написать интеграционные тесты для проверки отправки сообщения на почту.

## REST API

Реализованы следующие HTTP-запросы:

- GET /api/users — получить список всех пользователей.
- GET /api/users/{id} — получить пользователя по ID.
- POST /api/users — создать нового пользователя.
- PUT /api/users/{id} — обновить данные пользователя.
- DELETE /api/users/{id} — удалить пользователя.

Для работы с данными используются:

- UserCreateRequest — DTO для создания пользователя.
- UserUpdateRequest — DTO для обновления пользователя.
- UserResponse — DTO для ответа клиенту.

## Валидация и обработка исключений

Валидация входных данных реализована с помощью Jakarta Bean Validation.

Проверяются:

- Имя пользователя — обязательное поле, максимум 100 символов.
- Email — обязательное поле, проверяется формат и длина.
- Возраст — от 1 до 150 лет.
- ID пользователя — должен быть положительным числом.

Для консольного приложения и REST API используются единые правила валидации через DTO.

Реализована централизованная обработка исключений с помощью GlobalExceptionHandler.

Предусмотрены следующие HTTP-статусы:

- 200 OK — успешное получение или обновление пользователя.
- 201 Created — успешное создание пользователя.
- 204 No Content — успешное удаление пользователя.
- 400 Bad Request — некорректные входные данные.
- 404 Not Found — пользователь не найден.
- 409 Conflict — пользователь с указанным email уже существует.

## Запуск приложения

Для запуска необходимы Java 21, Maven и подключение к PostgreSQL.

Настройки подключения к базе данных передаются через переменные окружения:

- DB_URL — адрес подключения к базе данных.

- DB_PASSWORD — пароль базы данных.

Запуск REST API:

Приложение можно запустить через класс JpaProbeApplication.

По умолчанию REST API доступен по адресу:

`http://localhost:8080/api/users`

Консольное приложение запускается через класс Main.

## Подключение к базе данных

Проект использует PostgreSQL, размещённую в [Neon](https://console.neon.tech/), и Hibernate ORM для взаимодействия с базой данных.

### Доступ к Neon

Для работы с общей базой данных необходимо получить доступ к проекту `user-service` в организации `user-service-team`.

База данных: `user_service_db`.

Доступ к проекту предоставляется администратором команды через приглашение в Neon.

### Настройка подключения

Параметры подключения передаются через переменные окружения:

| Переменная    | Назначение                        |
|---------------|-----------------------------------|
| `DB_URL`      | JDBC URL подключения к PostgreSQL |
| `DB_USER`     | Имя пользователя PostgreSQL       |
| `DB_PASSWORD` | Пароль пользователя PostgreSQL    |

Для настройки в IntelliJ IDEA:

1. Открыть **Run → Edit Configurations**.
2. Создать конфигурацию **Application** для класса `ru.aston.Main` или выбрать существующую.
3. В поле **Environment variables** указать `DB_URL`, `DB_USER`, `DB_PASSWORD`.
4. Сохранить конфигурацию.

Пример JDBC URL:

`jdbc:postgresql://<host>/user_service_db?sslmode=require`

Актуальные параметры подключения можно получить в Neon Console через **Connect** после предоставления доступа.

**Важно:** не добавлять пароли и другие секретные данные в Git.

### Конфигурация Hibernate

Файл `user-service/src/main/resources/hibernate.cfg.xml` содержит настройки Hibernate.

Класс `ru.aston.homework.config.HibernateUtil` отвечает за создание `SessionFactory` и получение параметров подключения из переменных окружения.

Используется `hibernate.hbm2ddl.auto=update` для автоматического обновления схемы базы данных на основе зарегистрированных сущностей. Изменения структуры общей базы необходимо согласовывать с командой.
